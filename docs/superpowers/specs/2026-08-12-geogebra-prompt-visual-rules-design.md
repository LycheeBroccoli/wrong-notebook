# GeoGebra prompt 视觉呈现规则补充设计

**日期**：2026-08-12
**范围**：仅改 `src/lib/ai/prompts.ts` 的 `DEFAULT_GEOGEBRA_PROMPT`
**目标**：让 AI 生成的 GeoGebra 命令不仅「画对几何关系」，还要「画得像原图、看得清」

## 背景与根因

用户在 `error-items/[id]` 页用 GeoGebra 重绘截图几何图形时反馈三个问题（证据：DB 记录 `cmsowkw4j00096obiiyvir957`，题目「D 是等边三角形 ABC 外一点，AD=3，CD=2，求 BD 最大值」）。根因全部在 AI 生成的命令内容，不是前端 `geogebra-demo.tsx` 的 bug（前端只忠实喂命令给 applet）：

1. **顶点标签位置与原图不符**：AI 生成 `A=(0,0)`、`B=(a,0)`、`Polygon(A,B,3)`。`Polygon(A,B,3)` 按 GeoGebra 逆时针规则派生第三顶点 C 在「A→B 左侧」；A→B 水平向右，左侧是 y 正方向，故 C 落在正上方。原图是「A 顶、B 左、C 右」，AI 选错了基准边（把顶点 A 当底边端点）。
2. **Text 提示词缩放时与 Slider 分离、遮挡图形**：`a = Slider(...)` 是 applet 内置 UI（不随数学坐标缩放），`Text("…", (x,y))` 绑死数学坐标（随缩放移动），机制不同必分离；AI 把 Text 坐标写在 `(-1.5, 5.3)` 压在图形上方区域。
3. **标签灰色不突出**：GeoGebra 点标签文字颜色是 applet 默认灰色，无命令可直接改；AI 命令里没有任何增强标签可读性的手段。

**共同根因**：`DEFAULT_GEOGEBRA_PROMPT` 重几何约束、轻视觉呈现——顶点方位布局、Text/Slider 定位机制、标签可读性三块是空白。

## 设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 注释标注 | **不加** `【几何约束】`/`【视觉呈现】` 标记 | 用户要求减少 prompt 篇幅 |
| 修复路线 | **纯改 prompt**，不动 service 层/前端 | 用户要求轻量、可维护；视觉规则与现有几何规则同范式（都靠 prompt + AI 自检） |
| 问题 1 策略 | 先分析原图顶点方位再画 | 最贴合「画得像原图」目标 |
| 问题 2 策略 | Text 放视图边缘边距区 | 简单可维护；纯 prompt 可达 |
| 问题 3 策略 | 点深色+放大间接增强 | GeoGebra 无 setLabelColor，纯 prompt 只能间接 |

## 不改动项

- `src/lib/ai/geogebra-commands.ts`（`normalizeGeogebraCommands` 后处理不动）
- `src/components/geogebra-demo.tsx`（前端不动）
- `src/__tests__/unit/ai/geogebra-commands.test.ts`（测试不动）
- 不加 service 层视觉后处理（不算 Text 包围盒避让、不自动给点补色）

## 改动详情

全部落在 `src/lib/ai/prompts.ts` 的 `DEFAULT_GEOGEBRA_PROMPT`（512-694 行）。三处规则补充 + 一处自检清单。不加任何分类标注，不动现有结构。

### 补充 1：顶点方位匹配原图（问题 1）

**位置**：「GeoGebra 绘图命令」的正多边形条目（现 555 行附近）后。

**新增规则文本**（追加到正多边形条目说明末尾）：

> 用 `Polygon(A, B, n)` 前，先判断原图里每个顶点的相对方位（谁在顶/左/右/底），据此选哪条边作基准边、A 与 B 谁在左谁在右。方向规则：`Polygon(A, B, n)` 按逆时针派生，第三顶点（及后续顶点）落在「从 A 走向 B 时的左侧」。例：原图 A 是顶点、B 在左下、C 在右下，应选 BC 为基准边且 B 在左、C 在右（B→C 向右，左侧是上方），第三顶点派生到上方，与原图 A 的位置一致。严禁随意挑两个点作基准边而不核对派生顶点落点是否与原图一致。派生顶点的点名由 GeoGebra 自动分配，若自动点名与原图不符，用 `setCaption("自动名", "原图名")` 重命名标签文本（此为 setCaption 的正当用途，与「变换点用撇号命名不用 setCaption 绕路」不冲突——后者针对反射/位似/旋转的撇号变换点）。

**关键约束新增条目**（追加到「关键约束」末尾，编号续）：

> 16. **顶点方位与原图一致**：用 `Polygon(A, B, n)` 构造正多边形前，必须先判断原图各顶点方位，选对基准边与 A/B 顺序，使派生顶点落到原图对应位置。吐 commands 前自检：派生顶点落点是否与原图一致？

### 补充 2：Text 提示词放视图边缘（问题 2）

**位置**：「GeoGebra 绘图命令」的文本条目（现 567 行附近）后，与滑动条条目（现 568 行）相关说明合并。

**新增规则文本**（追加到文本条目说明末尾）：

> `Text("说明", (x, y))` 的坐标必须放在视图最上方或最下方的边距区（y 接近 yMax 或 yMin 但不超出 `setCoordSystem` 范围），不得压在图形主体上。定位机制差异：Text 坐标随视图缩放/平移移动，`Slider` 是 applet 内置 UI 不随数学坐标移动，两者机制不同，故 Text 不得试图靠近 Slider，而应独立放视图边缘。

**关键约束新增条目**：

> 17. **Text 提示词避让图形**：`Text("…", (x, y))` 坐标必须落在视图最上方或最下方的边距区，不得压在图形主体上。吐 commands 前自检：Text 坐标是否在边缘边距区？

### 补充 3：点深色+放大增强标签可读性（问题 3）

**位置**：「Applet API 设置命令」的 setColor（现 580 行）/ setPointSize（现 583 行）条目后。

**新增规则文本**（追加到 setPointSize 条目说明末尾，或紧随其后新增一条）：

> 所有关键点（题目出现的 A/B/C/D 等点名）必须 `setColor("名", 深色)` + `setPointSize("名", 5)`（深色取黑 `0, 0, 0` 或深红 `200, 30, 30` 等），让点本身显眼。GeoGebra 标签文字颜色无法用命令直接改（applet 默认灰），只能靠点本身深色+放大间接增强标签可读性。

**关键约束新增条目**：

> 18. **关键点深色+放大**：题目出现的所有点名必须 `setColor(深色)` + `setPointSize(5)`，间接增强标签可读性。吐 commands 前自检：关键点是否都设了深色+放大？

### 自检清单整合

上述 16/17/18 三条关键约束即构成「视觉自检清单」，分散在「关键约束 CRITICAL RULES」末尾，与现有 1-15 条（几何约束为主）并列。不单设「视觉自检」小节，避免改结构。

## 验证方式

- **单元测试**：现有 `geogebra-commands.test.ts` 不动（视觉规则靠 prompt，不进 normalizer）。可选：加一个文档级测试，断言 `DEFAULT_GEOGEBRA_PROMPT` 文本包含三条新规则的关键句（防回归删除），但非必需。
- **人工验证**：对 `cmsowkw4j00096obiiyvir957` 重新生成 GeoGebra 命令，确认：①顶点方位与原图一致；②Text 在边缘；③关键点深色+放大。
- **回归**：跑现有 `geogebra-commands.test.ts` 确保 normalizer 行为不变（应全绿，因为没动 normalizer）。

## 遗留项（本次不修）

- **标签文字颜色根治**：需前端操作 applet XML 改 label 颜色，属前端层改动，本次不做。本次用「点深色+放大」间接增强，已显著改善可读性。
- **Text 真正跟随 Slider**：需前端 listener 绑定 Slider 位置到 Text，属前端层改动，本次不做。本次用「Text 放边缘」避让，已解决遮挡。
- **service 层视觉兜底**：用户明确倾向不动，保持轻量。若未来发现 AI 偶发不遵守视觉规则，可再考虑给 `normalizeGeogebraCommands` 加确定性后处理（如检测 Text 坐标压图形区则移到边缘）。
